Se debe contemplar que, se implementará un esquema de rotación de datos. Al finalizar el período activo (establecido en un año), los datos almacenados en acceso rápido serán trasladados a almacenamiento en frío, y se cargarán nuevos datos para mantener la disponibilidad en acceso rápido. La información sobre la rotación de datos se proporciona únicamente como referencia y no forma parte del alcance del servicio a ser contratado.

El sistema de almacenamiento debe ser compatible con S3 (S3-compatible storage).

  • El requerimiento de alta disponibilidad (HA) aplica a los nodos de procesamiento (processing nodes) y puede cumplirse dentro de una región de nube que ofrezca zonas de disponibilidad (availability zones), este requerimiento aplica específicamente a estos nodos de procesamiento (processing nodes), no al sistema de almacenamiento.
  • La data fría se gestionará de forma que mantenga un tamaño constante durante la vigencia del contrato, sin contemplar crecimiento anual.

La escalabilidad mencionada durante el año del contrato hace referencia a las capacidades estándar de un servicio IaaS, como el aprovisionamiento dinámico de recursos bajo demanda.

El despliegue será realizado utilizando la interfaz del clúster de Kubernetes y la API, así como la API de almacenamiento de objetos S3. El Operador deberá contar con acceso directo, ya sea mediante VPN o interfaz web, a las APIs de Kubernetes y S3. Se recomienda el acceso mediante VPN. Además, se debe considerar que los nodos de Kubernetes deberán tener acceso a internet para descargar las imágenes de aplicaciones Middleware relevantes y los datos que se deberán transferir al almacenamiento S3.

Información adicional sobre parámetros de almacenamiento (Hot Storage, Cold Storage y Block Storage):

  • Para Hot Storage y Cold Storage, el tamaño promedio de los objetos oscila entre 100 MB y 1 GB, con un máximo de 8 GB.
    • Se debe considerar que son frecuentes las lecturas parciales con tamaños entre 16 KB y 1 MB, por lo que el Hot Storage deberá estar optimizado para accesos parciales.
  • En Cold Storage, una solicitud promedio de recuperación corresponderá a 20 TB, y una vez recuperados, los datos deberán ser accesibles con el mismo desempeño y patrones de acceso que en el Hot Storage.
  • En cuanto a Block Storage (SSD – PVC):
    • Se recomienda un tamaño de bloque de 16 KB, adecuado para operaciones de I/O aleatorias (ejemplo: acceso a bases de datos).
    • El patrón de uso aceptado es de 70% lectura y 30% escritura.
    • Para entornos con VMFS, no existen requisitos específicos de tamaño de bloque; se acepta el valor por defecto de 1 MB.

Especificaciones de Almacenamiento de Objetos (Object Storage):

Para el almacenamiento caliente de objetos (hot storage), el sistema deberá garantizar latencias máximas de 100 milisegundos para operaciones de lectura y 200 milisegundos para operaciones de escritura. Este almacenamiento será utilizado para el acceso frecuente a datos procesados y metadatos del sistema, por lo que debe mantener estos niveles de rendimiento de forma consistente bajo condiciones de carga operativa normal.
