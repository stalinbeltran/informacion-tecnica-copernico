Data Flow from Ingestion to Processing

Flujo de datos de la ingesta al procesamiento según el nivel elegido (solo metadatos, copia o calibración), y cómo el catálogo STAC unifica el acceso independientemente de dónde resida el dato.

pp. 10–11

The data flow from ingestion to processing reflects a flexible and modular design that accommodates various levels of data ingestion, metadata registration, dataset copying, and dataset calibration. These levels influence how data moves through the system, ensuring

that ingestion workflows align with the dataset's intended use while maintaining efficiency and interoperability across components.

Data ingested through the Data Ingestion component follows a structured workflow. For metadata registration, only metadata is validated, cataloged, and indexed within the Data Discovery and Access component, enabling users to discover and retrieve datasets directly from their original sources. For dataset copying, the ingestion workflow includes the validation, storage, and indexing of datasets within the platform's S3-compatible object storage system. In scenarios involving dataset calibration, additional processing steps are executed during ingestion to prepare the data for specialized analyses or workflows. These calibrated datasets are also stored locally, accompanied by updated metadata reflecting the calibration processes.

The Data Discovery and Access component ensures that all ingested or registered data is indexed and made searchable using the STAC specification. This cataloging process provides a unified interface for users to explore datasets, regardless of their physical storage location.

When a user initiates a processing task, the Data Processing component retrieves the necessary datasets from the storage system or external access points defined during ingestion. The retrieval process is optimized to ensure that metadata alignment and dataset integrity are maintained. For locally stored datasets, the system uses Argo Workflows to orchestrate the execution of EO algorithms as defined in the Application Repository. These workflows manage dependencies and processing logic, ensuring that tasks such as data analysis, transformation, and visualization are performed.

For datasets registered via metadata only, the processing component retrieves data directly from the external source as needed, ensuring interoperability with distributed data systems. In cases involving calibrated datasets, the processing workflows leverage the pre-processed data for further analysis, reducing the computational overhead required during execution.

The platform’s modularity ensures that the flow of data from ingestion to processing remains adaptable to varying user needs and operational requirements. Whether handling metadata-only ingestion for data discovery or managing full ingestion and calibration workflows for complex processing tasks, the system maintains integration across its components. This flexibility supports a wide range of use cases, from rapid metadata harvesting to large-scale EO data analysis.
