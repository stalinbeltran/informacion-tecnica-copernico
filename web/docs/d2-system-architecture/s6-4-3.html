Execution as a Service

Ejecución como servicio: la aplicación se expone vía OGC API Processes, permitiendo su integración con otros servicios geoespaciales.

pp. 64–65
  • Purpose: In this scenario, applications are deployed as services that can be accessed via APIs, particularly through the OGC API Processes interface. This approach makes EO applications available as web services, enabling integration with other geospatial services and tools.
  • Implementation: The CWL blueprint ensures that the application package is compatible with OGC standards, facilitating deployment as a standardised service.

This allows other users and systems to interact with the application through a well-defined API, enhancing interoperability and usability.

  • Advantages: Broad accessibility, interoperability with other platforms, and the ability to offer EO applications as a service to a wide audience.
