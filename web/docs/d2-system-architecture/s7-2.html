Common Workflow Language (CWL)

CWL y sus motores de ejecución: cwltool (referencia, local), Toil (HPC y nube) y Calrissian (nativo de Kubernetes, el elegido para escalar).

Calrissian
pp. 72–73

The Common Workflow Language (CWL) is integral to the CopernicusLAC platform, providing a standardised approach for defining and executing complex data processing workflows. CWL's primary strength lies in its ability to describe workflows in a way that is both platform-independent and highly reproducible. This standardisation ensures that workflows can be consistently executed across a variety of environments, from local development setups to large-scale cloud deployments.

To execute CWL workflows, several tools and engines have been developed, each optimised for different environments and use cases. These tools ensure that the workflows described in CWL can be executed at scale, with support for parallel processing and integration with modern infrastructure:

  • cwltool: cwltool is the reference implementation of CWL, developed by the CWL project itself. It is a lightweight, Python-based tool designed for testing and running CWL workflows on a local machine. While cwltool is ideal for development and small-scale execution, it lacks the scalability required for large, production-grade environments.
  • Toil: Toil is a workflow engine designed for scalable, distributed computing environments. It supports the execution of CWL workflows across multiple compute nodes, making it suitable for high-performance computing (HPC) environments and cloud-based deployments. Toil integrates well with batch processing systems like SLURM and cloud services such as AWS Batch, allowing for flexible and powerful execution strategies.
  • Calrissian: Calrissian is a specialised CWL implementation designed to run within a Kubernetes cluster. Its primary goal is to harness the power of Kubernetes to execute workflows, taking full advantage of high-capacity clusters to run multiple steps in parallel. Calrissian is highly scalable and can dynamically allocate resources based

on the requirements of each workflow step, making it an ideal choice for environments where large-scale data processing tasks need to be executed reliably.

Calrissian integrates with Kubernetes, allowing it to handle the orchestration of containers that execute individual workflow steps. By leveraging Kubernetes' built-in features, such as auto-scaling, load balancing, and fault tolerance, Calrissian ensures that workflows are executed with optimal resource utilisation and minimal downtime. This makes it particularly valuable for the CopernicusLAC platform, where the ability to scale workflows across a distributed infrastructure is crucial.
