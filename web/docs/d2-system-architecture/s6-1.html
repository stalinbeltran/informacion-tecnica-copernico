Overview

El proceso encapsula código, dependencias, configuración, metadatos y entorno de ejecución siguiendo las buenas prácticas OGC de EO Application Packaging y EOEPCA; cuatro pasos: definir workflows, crear el paquete, publicarlo en Harbor y versionarlo.

pp. 59–60

Application packaging in the CopernicusLAC platform is a systematic process that encapsulates all components necessary for EO data processing workflows. This includes the application code, dependencies, configuration files, metadata, and runtime environments. The primary objective is to create standardised, portable packages that can be deployed consistently across diverse environments, from local development setups to cloud-based infrastructures and to be deployed as a web service.

This process adheres to the Best Practices for Earth Observation Application Packaging7 as defined by the Open Geospatial Consortium (OGC) and the EO Exploitation Platform Common Architecture8 (EOEPCA) spearheaded by the European Space Agency (ESA). These guidelines ensure that EO applications are reproducible and portable across different execution scenarios.

The application packaging process leverages several key technologies:

  • CWL: Standard for describing the workflows and tools used in EO data processing. It ensures that applications are portable and can be executed consistently.
  • GitLab: GitLab is used for version control, managing the application code, workflows, and configuration files. It also handles Continuous Integration (CI) pipelines that automate the packaging process.
  • Harbor: Harbor serves as the container registry where Docker images of the packaged applications are stored. These images include all necessary runtime environments and dependencies.
  • Kubernetes and Helm: These tools are used to deploy the packaged applications within the platform’s cloud environment. Kubernetes orchestrates the containers, while Helm manages the deployment configurations.

The packaging workflow involves several key steps:

  • Defining Workflows and Dependencies: The first step involves defining the data processing workflows using CWL. This includes specifying tools, input/output files,

and dependencies required by the application. CWL provides a standardised syntax that ensures workflows are portable and reproducible.

  • Creating Application Packages: Application code, dependencies, and configuration files are packaged into a Docker image. This image is created using Dockerfiles, which specify the environment and dependencies required by the application.
  • Storing Packages in Harbor: The Docker image, along with its metadata, is pushed to the Harbor container registry. Harbor ensures that these packages are securely stored and easily retrievable for deployment.
  • Versioning: Each application package is versioned using GitLab. Version control allows developers to track changes over time, ensuring that different versions of an application can be maintained, tested, and deployed as needed.
