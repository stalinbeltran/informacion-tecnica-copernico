Technologies Used

CWL define los workflows, Argo Workflows los orquesta y STAC estandariza el catálogo; los tres se adaptan a cada nivel de ingesta.

pp. 39–40

The data ingestion process in the CopernicusLAC platform relies on several key technologies that enable flexible and efficient workflows, accommodating different levels of ingestion, metadata registration, dataset copying, and dataset calibration. These technologies ensure that the platform can adapt dynamically to the specific requirements of each dataset and operational scenario:

  • Common Workflow Language (CWL): CWL is used to define the workflows that automate data ingestion tasks. This includes specifying how data is retrieved, validated, and processed based on the ingestion level:
    • For metadata registration, CWL workflows focus on retrieving and validating metadata for cataloging.
    • For dataset copying, CWL workflows include tasks for downloading, integrity checks, and storing the datasets locally.
    • For calibration workflows, additional steps for processing and transformation, such as format conversion or quality enhancements, are included.
  • Argo Workflows: Argo orchestrates the ingestion pipelines, ensuring that each step in the process is executed in the correct order and that dependencies are managed effectively. Its Kubernetes-native design provides the scalability required to handle the dynamic demands of different ingestion levels. For example:
    • Metadata-only ingestion workflows are lightweight and emphasize speed and compliance.
    • Full dataset ingestion workflows manage larger data volumes and include validation for data integrity and completeness.
    • Calibration workflows leverage Argo’s flexibility to include custom processing tasks tailored to specific analytical needs.
  • STAC (SpatioTemporal Asset Catalog): STAC is used to organise and catalog all ingested data, regardless of its ingestion level. Metadata from all ingestion workflows is standardized and indexed to ensure discoverability and accessibility through the platform. For metadata registration, STAC entries point to external data sources, while for dataset copying and calibration, the entries include details about locally stored datasets or pre-processed outputs..
