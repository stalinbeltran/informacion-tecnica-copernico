D2 · System Architecture Description · Capítulo 3.3.2

Implementation

Tres piezas: bus de eventos (Argo Events sobre Kafka), motor de workflows (Argo Workflows con CWL) y motor de ejecución de aplicaciones con las funciones de despliegue (OGC API Processes Parte 2) y ejecución (Parte 1).

pp. 22–24

The implementation of the Data Processing component involves several key elements designed to facilitate scalable data processing:

  • Event Bus: The Argo Events event bus, powered by Apache Kafka, handles the communication between different parts of the system. It ensures that data is passed

from the ingestion component to the processing workflows, and it also handles notifications and triggers for processing tasks.

  • Processing Workflow Engine: The processing workflow engine, implemented using Argo Workflows, manages the execution of complex processing pipelines. These pipelines are defined using the CWL and orchestrate various tasks such as data validation, transformation, and analysis.
  • Application Execution Engine: The application execution engine provides the web service interface (OGC API Processes) that is called by the front-end services to execute specific data processing applications. It also calls the Processing Workflow Engine to execute EO applications defined as application packages. The application execution engine has two distinct functionalities: deployment and execution.

The event bus is responsible for handling the communication and data flow between different components of the data processing pipeline. Argo Events uses Apache Kafka to manage the flow of messages and events, ensuring that data is routed and processed in a timely manner.

  • Data Flow Management: The event bus manages the flow of data from the Data Discovery and Access Component to the processing workflows and applications.
  • Notification and Triggering: It handles notifications and triggers for processing tasks, ensuring that workflows are executed when data becomes available.

The processing workflow engine manages the execution of complex data processing workflows. It uses Argo Workflows to define and orchestrate these workflows, ensuring that tasks are executed in the correct order and that dependencies are managed.

  • Workflow Definition: Workflows are defined using the CWL, providing a standard and portable way to specify processing tasks.
  • Orchestration: Argo Workflows orchestrates the execution of these workflows, managing dependencies, scheduling tasks, and handling retries and failures.
  • Event-Driven Workflow: Argo Events ensures that specific processes or tasks are initiated based on predefined events, maintaining system responsiveness and efficiency.

The Application Execution Engine provides the web service interface (OGC API Processes) that is called by the front-end services to execute specific data processing applications. It manages the execution of these applications, ensuring they are accessible via standardised APIs, and it calls the Processing Workflow Engine for executing complex workflows.

  • Deployment:
    • Functionality: The deployment functionality handles the submission of EO application packages described using CWL. This involves specifying parameters, software items, executables, dependencies, and metadata.
    • Interface: The deployment interface is defined in the OGC API Processes Part 2 standard, outlining the protocols and methods for deploying EO applications within the environment.
    • Setup: Ensures applications are set up in the environment and ready for execution.
  • Execution:
    • Functionality: The execution functionality initiates and manages the processing jobs. Users interact with this functionality to execute the deployed EO applications, providing necessary input parameters and initiating the processing tasks.
    • Interface: The execution interface is aligned with the guidelines set in OGC API Processes Part 1, detailing how users can initiate and manage processing jobs within the environment.
    • Management: Handles task scheduling, monitoring, and the retrieval of outputs.
