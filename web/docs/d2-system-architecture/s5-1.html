SpatioTemporal Asset Catalog (STAC)

Qué es STAC y por qué se adopta: items, assets, colecciones, extensiones, enlaces, bounding boxes espacio-temporales y naturaleza flat-file; incluye las extensiones Web Map Links y Authentication (URLs firmadas).

pp. 48–50

STAC serves as a standardised representation for all these geospatial assets and their associated metadata. Metadata, in this context, includes information about when and where a dataset was collected, the type of sensor used, its resolution, and other descriptive details. By adhering to a common specification provided by STAC, various organisations and platforms are representing their geospatial assets in a manner that's consistent and easily comprehensible. This uniformity ensures that different datasets, even if they are from diverse sources or missions, can be understood and compared with minimal friction in a federated landscape.

One of the defining features of STAC that is extremely relevant for CopernicusLAC is its flat-file nature, meaning it is stored alongside the data it describes, usually as a JSON file. This co-location ensures that the metadata remains directly accessible and linked to its corresponding dataset. Within a STAC item, individual assets are detailed, representing various components or layers of a geospatial product, such as RGB images, thermal bands, or other data files. By defining these assets, STAC provides users with a comprehensive view of what each dataset comprises, aiding in precise data retrievals.

The STAC API optimises geospatial data accessibility with a dynamic interface for users and systems to search and access the catalogued assets. Adhering to modern RESTful principles, the API facilitates interactions with STAC Items and Collections. By using this interface, users can perform real-time searches, refining their queries based on spatiotemporal parameters, specific asset types, or even custom metadata fields. This dramatically reduces the time taken to locate pertinent datasets, streamlining the entire data discovery process.

In this context, STAC ensures that geospatial data can be easily catalogued, discovered, and accessed in a standardised manner by adhering to certain conventions and rules:

  • STAC Item: The core building block of STAC, a STAC Item represents a spatiotemporal asset and contains a collection of metadata. Each item is described using JSON, a lightweight data-interchange format.
  • Assets: Within each STAC Item, assets define the actual data files. They might refer to different bands of satellite imagery, resolution levels, or even derived products.

Assets specify URIs for data retrieval, as well as media type identifiers to convey the nature of the data.

  • STAC Collection: This is a collection of STAC Items, with metadata about the aggregation of items, potentially describing properties like the spatial and temporal extents of all the contained items.
  • Core and Extensions: STAC is designed to be extensible. While it has a core specification that ensures basic functionality and interoperability, extensions can be added to cater to specific use-cases, like satellite, label, or point cloud extensions.
  • Linking Mechanism: STAC uses a consistent linking mechanism. Every STAC item, catalog, and collection contains an array of links, which can be used to navigate to related items, parent or child catalogues, or even out to other specifications.
  • Spatial and Temporal Bounding Boxes: Each STAC item provides spatial bounds (usually described by a bounding box or polygon) and temporal bounds (start and end times) to aid in discovery based on space and time criteria.
  • Flat-File Nature: As previously mentioned, STAC specifications are often stored as flat JSON files alongside the data they describe. This co-location ensures rapid access to metadata without necessitating complex database queries.
  • Self-Describing JSON: STAC relies on self-describing JSON structures, meaning each file is intended to be understood in isolation. This makes it scalable and easy to parse without deep dependencies.

A primary advantage of STAC is that it defines an extensible vocabulary, ensuring metadata consistency across varied datasets. Given the diverse sources of EO data, from an assortment of sensors, platforms, and missions, and ever-growing use cases, there's a potential for metadata variations. STAC's framework compels providers to use a harmonised set of conventions.

In addition to the core functionalities of STAC, the catalogue incorporates the "Web Map Links Extension"4. This extension enriches the STAC catalog by adding an additional link element within the STAC item structure.

The link elements provided together in the STAC Item points to web map services that are capable of visualising the geospatial data described by the item. It allows client applications to directly access and visualise the spatial data through interactive map services, enhancing their understanding and interpretation of the data.

To bolster the security and controlled access to the geospatial data the catalog also integrates the use of signed URLs through the STAC "Authentication Extension"5. The STAC Authentication Extension's signed URL information is specifically integrated into the STAC for secure data downloading. This mechanism ensures that access to spatial data assets is tightly controlled:

  • Signed URL Generation: When a user requests access to an asset, the system generates a signed URL. This URL is uniquely created for the specific request and user, embedding security credentials directly into the URL.
  • Temporary Access: Each signed URL is valid for a limited time, ensuring that access to the asset is temporary and controlled. This time-bound nature of URLs enhances security by minimising the risk of unauthorised access.
  • Direct and Secure Data Download: The signed URLs allow users to download assets directly from the catalog without the need for additional layers of authentication at the point of download, streamlining the user experience while maintaining security.
