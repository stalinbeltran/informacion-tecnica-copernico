Common Workflow Language (CWL)

CWL en profundidad: las clases CommandLineTool y Workflow, sus componentes (inputs, outputs, baseCommand, steps, requirements) y dos ejemplos completos de cálculo de NDVI.

CódigoNDVI
pp. 60–62

The Common Workflow Language (CWL) offers a standardised and versatile approach to creating, sharing, and executing workflows. Developed to address the complexities of diverse computational environments, CWL provides a common ground for describing workflows, regardless of the underlying execution platform.

CWL's strength lies in its ability to facilitate the creation of executable workflows through a standardised syntax. For instance, imagine a scenario where an Earth observation researcher wants to process satellite imagery to calculate vegetation indices like NDVI. Using CWL, they can define the necessary steps, such as data loading, image preprocessing, and index calculation, in a single CWL document. This document acts as a blueprint that captures the sequence of operations, their inputs, outputs, and dependencies. This standardised approach not only simplifies the communication of workflows but also fosters collaboration among multidisciplinary teams.

One of the most significant advantages of CWL is its prowess in enhancing the portability of workflows across various platforms. Take the example of a remote sensing algorithm for cloud detection. By encapsulating the algorithm's steps and dependencies within a CWL document, the workflow becomes platform-agnostic. Whether executed on a local machine, a cloud instance, or within a containerized environment, the workflow remains consistent. This cross-platform compatibility eliminates the challenges of software version disparities and configuration differences, ensuring reproducible results regardless of the execution context.

CWL encompasses two main classes that define the structure of workflows:

  • CommandLineTool: Represents a command-line executable, complete with input parameters, command-line arguments, and output specifications. This class is essential for encapsulating standalone processing steps, such as running image processing algorithms.
  • Workflow: Defines a sequence of connected steps, including inputs, outputs, and dependencies. Workflows allow the integration of multiple CommandLineTools and provide a holistic representation of complex processing pipelines.

The CommandLineTool class within the CWL serves as a fundamental building block for creating executable workflows. It represents a self-contained command-line executable, encapsulating the necessary details to execute a specific processing step. This class proves particularly useful for isolating individual algorithms or tasks within a larger workflow.

In the definition of a CWL CommandLineTool, several essential components are outlined:

  • inputs: This section describes the input parameters required by the command-line tool. Inputs can encompass various data types such as file references, strings, integers, and more.
  • outputs: The outputs section specifies the expected output files or values generated by the tool after execution.
  • baseCommand: This field defines the command that needs execution, along with its initial arguments.
  • arguments: Additional command-line arguments that are appended to the base command during execution.
  • stdout, stderr: These fields designate the paths for standard output and standard error, facilitating the capture of messages and errors.

For instance, in the context of calculating the Normalised Difference Vegetation Index (NDVI) from input satellite imagery, the following CWL representation can be observed:

cwlVersion: v1.2
class: CommandLineTool
baseCommand: python calculate_ndvi.py
inputs:
 - id: input_image
      type: File
 - id: output_ndvi
   type: File
outputs:
  - id: output_ndvi
    type: File
stdout: output.log
stderr: error.log

The Workflow class within CWL empowers the creation of intricate workflows by connecting multiple tools or steps. Workflows provide a means to orchestrate the execution of CommandLineTools, establishing a sequence of operations aimed at achieving a specific task. Workflows can include parallel processing, conditional branching, and the management of data dependencies.

In a CWL Workflow definition, the primary components include:

  • inputs: This field specifies the inputs that the workflow anticipates.
  • outputs: The outputs section outlines the results generated by the workflow.
  • steps: This section defines an array of steps, representing the tools or workflows being executed. Each step includes the tool's identifier and its inputs.
  • requirements: Describes the requirements necessary for executing the workflow, such as software dependencies or computational resources.

Expanding upon the CommandLineTool example, consider the creation of a Workflow that pre-processes an image and subsequently calculates NDVI using distinct tools:

cwlVersion: v1.2
class: Workflow
inputs:
  - id: input_image
    type: File
outputs:
  - id: output_ndvi
    type: File
steps:
  preprocess:
    run: preprocess.cwl
    in:
      input_image: input_image
    out: [preprocessed_image]
calculate_ndvi:
  run: calculate_ndvi.cwl
  in:
    input_image: preprocess/preprocessed_image
  out: [output_ndvi]

In this example, the Workflow interconnects two steps, 'preprocess' and 'calculate_ndvi'. Each step references a CommandLineTool definition (preprocess.cwl and calculate_ndvi.cwl) that executes distinct tasks. The output of the 'preprocess' step serves as the input for the 'calculate_ndvi' step.

The CommandLineTool and Workflow classes in CWL coalesce, offering a platform for creating structured workflows that encompass both individual processing steps and complex orchestrations. This combined approach empowers users to craft, share, and execute data processing workflows with ease, enabling execution across diverse platforms and environments.
