D2 · System Architecture Description · Capítulo 3.4.2

Implementation

GitLab guarda los paquetes como artefactos de CI con control de versiones y metadatos; Harbor actúa como registro de contenedores; ambos aplican control de acceso.

pp. 26

The implementation of the Application Registry involves several key elements designed to facilitate the management and retrieval of EO application packages:

  • GitLab for Application Packages: GitLab is used to store the application packages as Continuous Integration pipeline artifacts, including the CWL descriptions, code, and configuration files. This ensures that all components required for the execution of EO applications are version-controlled and easily accessible.
  • Harbor as a container registry: Harbor serves as the cloud-native container registry to store and manage the container images associated with the application packages. This ensures that the application containers are easily accessible and deployable.
  • Metadata Management: Comprehensive metadata for each EO application package is stored within GitLab, including details such as version, dependencies, configuration parameters, and usage instructions.
  • Version Control: GitLab provides version control for application packages, allowing users to track changes, revert to previous versions, and ensure compatibility with different processing environments.
  • Access Control: Both GitLab and Harbor implement access control mechanisms to ensure that only authorised users can add, update, or retrieve application packages and container images. This ensures the security and integrity of the stored applications.
  • Search and Retrieval: GitLab's integrated search functionality allows users to quickly locate and access the application packages they need for deployment and execution. This may evolve towards a dedicated document oriented database.
